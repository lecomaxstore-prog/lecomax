# Private source library

Open **How it was built → My files**, or use **Open this lesson’s actual file** in a daily lesson. Search matches paths and source text. Results open at the matching line. Favourites save paths in the current browser; they do not duplicate code.

**Learn mode** is enabled by default. Click any code line to see what the recognized pattern does, why it is used, and a simple example. Previous/Next and the arrow keys move through the explanation; Home/End reach the first/last line. The selected line is included in the link. The file overview explains the file's general role. Turn Learn mode off for a quieter reader. French, English and Arabic follow the course language, including right-to-left layout.

Explanations use a local, deterministic reading guide in `lib/source-code-guide.ts`. They require no AI account or external requests. They explain recognizable syntax, not the author's unverified business intent; unfamiliar expressions explicitly ask for surrounding context. Examples are illustrative and are never executed.

The owner session and the separate owner-section unlock protect every library, content and tree request. Source is returned as text, never executed. The snapshot is outside `public` and is not imported by a client component.

Development reads saved project files, with a 15-second server cache. Click Refresh after saving a file in VS Code. Production reads `.source-library/catalog.json`, generated by `npm run source:refresh` and automatically by `npm run build`. Next.js includes this snapshot in the private API function bundles. A production deployment shows its build-time snapshot; it cannot read later edits on your computer.

Included folders: app, components, lib, scripts, docs, supabase, mobile/src, tests, plus selected root configuration files. Hidden files, credentials, keys, build outputs, dependencies, releases, lockfiles, symlinks and files over 2 MB are excluded. Common embedded credential patterns cause the entire file to be omitted. Content filtering is deliberately conservative and can omit test or configuration examples. Do not put actual credentials or customer records in source files.

If the online library reports unavailable, rebuild and redeploy with `npm run build`; do not upload the snapshot into public storage. No database schema or external storage service is needed. Updating a production snapshot requires another deployment.

Verification: run `node --test tests/source-code-guide.test.ts tests/source-library.test.ts tests/source-library-api.test.ts`, then `npm run smoke:source-library` with a local development server running. Set `COURSE_BASE_URL` if it uses a port other than 3000. The browser check verifies real file content, deep links, clickable explanations, keyboard navigation, all three languages, RTL, the mode toggle, filename and full-text search, saved favourites, and mobile layout using an isolated Chrome profile. It only creates test sessions for localhost.
